# **リレーション**

データベース内の異なるテーブル同士がどのように関連しているかを示すもの。リレーションにはいくつかの種類があり、それぞれが異なるデータの関係性を表している。代表的なものとして、「1対1」、「1対多」、「多対多」があります。

### **1対1**

1対1のリレーションとは、一つのテーブルの各レコードが別のテーブルのただ一つのレコードとだけ関連付けられることを意味します。ユーザーテーブルとプロフィールテーブルを例にすると、ユーザーは一つのプロフィールにのみ紐付けられ、一つのプロフィールが複数のユーザーに紐付けられることはありません。また、プロフィールも一人のユーザーにのみ紐づきます。このような場合、1対1の関係といえます。

### **1対多**

1対多のリレーションとは、一つのテーブルの各レコードが別のテーブルの複数のレコードと関連付けられることを指します。ユーザーテーブルと掲示板テーブルを例にすると、1ユーザーは複数の掲示板を投稿できるため（掲示板A, 掲示板B, ...）、ユーザーテーブルから見て掲示板テーブルは多の関係にあります。逆に、各掲示板は特定のユーザーによってのみ作成されるため、掲示板テーブルから見ると1の関係となります。このような場合、1対多の関係といえます。

# 多対多

今回の課題では直接使いませんが、知識として押さえておきましょう。

例えば、

```
User
Tag
```

があるとします。

1人のユーザーが複数のタグを持てて、

```
User A
 ├─ Ruby
 ├─ Rails
 └─ Docker
```

1つのタグにも複数のユーザーが存在する場合、

```
Ruby
 ├─ User A
 ├─ User B
 └─ User C
```

となります。

つまり、

```
User 多 ←→ 多 Tag
```

です。

これを**多対多**といいます。

Railsでは通常、中間テーブルを作って表現します。

（補足）

今回の課題では「1対多」が重要なので、多対多については今の段階では、

> 「多対多では間にもう1個テーブルを作ることが多い」

くらいの理解で大丈夫です。

# **アソシエーション**

アソシエーションとは、Railsのモデル間の関連性を定義する機能です。これにより、異なるモデル同士がどのように結びついているかを簡単に表現できます。主なアソシエーションには、has_one、has_many、belongs_to があります。それぞれの使い方と概念を理解し、モデル間の関係を適切に設定しましょう。

### **has_one**

has_oneアソシエーションは、1つのモデルが他のモデルと1対1で関連付けられる場合に使用します。例えば、ユーザーが1つのプロフィールを持つ場合、Userモデルに対してProfileモデルをhas_one :profile と定義します。これにより、Userモデルのインスタンスから関連づいたプロフィール情報を簡単に取得できます。

### **has_many**

has_manyアソシエーションは、1つのモデルが複数の他のモデルと関連付けられる場合に使用します。例えば、ユーザーが複数の掲示板を持つ場合、Userモデルに対してBoardモデルを has_many :boards と定義します。これにより、Userモデルのインスタンスからそのユーザーが投稿した複数の掲示板情報を簡単に取得できます。

### **belongs_to**

belongs_toアソシエーションは、1つのモデルが他のモデルに属する場合に使用します。例えば、掲示板がユーザーに属する場合、Boardモデルに対してUserモデルを belongs_to :user と定義します。これにより、Boardモデルのインスタンスから投稿者であるユーザー情報を簡単に取得できます。

### **アソシエーションを定義する理由・メリット**

アソシエーションを定義することによって、簡単な記述で関連レコードの呼び出しを行うことができます。例えば、Boardモデルのインスタンスから、紐づくユーザー情報を取得したい場合、アソシエーションの有無で下記のような違いがあります。

#### **アソシエーションがない場合**

```ruby
class BoardsController < ApplicationController
  def show
    @board = Board.find(:id)
    @user = User.find(@board.user_id)
  end
end
```

このコードでは、@board オブジェクトの user_id を取得し、その user_id を使って Usersテーブルから該当するユーザーを探しています。

#### **アソシエーションがある場合**

```ruby
class BoardsController < ApplicationController
  def show
    @board = Board.find(params[:id])
    @user = @board.user
  end
end
```

@board オブジェクトが持つ user アソシエーションを直接呼び出して、関連するUsersレコードを取得しています。アソシエーションが定義されているため、Railsが内部的に適切なSQLクエリを生成し、関連するユーザーのレコードを取得してくれます。

その他にも、一方のレコードが削除されると関連するもう一方のレコードも自動で削除できたりと、非常にメリットの大きなものになりますので、忘れずに定義を行うようにしてください。

# **バリデーション**

バリデーションとは、データがデータベースに保存される前に、そのデータが正しい形式や条件を満たしているかを確認する仕組みです。バリデーションを使用することで、不正なデータがデータベースに保存されるのを防ぎ、アプリケーションの信頼性を向上させることができます。Railsでは、モデルに対してバリデーションを定義することで、データの検証を簡単に行うことができます。代表的なバリデーションには、presence、length、uniqueness があります。

### **presence**

presenceバリデーションは、指定された属性が空でないことを確認するために使用します。例えば、ユーザー登録時に名前が必須である場合、validates :name, presence: true とモデルに記述します。これにより、名前が空であると保存が失敗し、エラーメッセージが表示されます。

### **length**

lengthバリデーションは、指定された属性の長さが特定の範囲内であることを確認するために使用します。例えば、パスワードの長さが8文字以上であることを要求する場合、validates :password, length: { minimum: 8 } とモデルに記述します。これにより、パスワードが短すぎると保存が失敗します。

### **uniqueness**

uniquenessバリデーションは、指定された属性の値が一意であることを確認するために使用します。「一意」とは、他に同じものがないことを意味します。データベースやプログラミングの文脈では、ある属性の値が他のどのレコードとも重複しないことを指します。例えば、ユーザー登録時にメールアドレスが既に存在しないことを要求する場合、validates :email, uniqueness: true とモデルに記述します。これにより、同じメールアドレスが既に登録されていると保存が失敗し、エラーメッセージが表示されます。

- app/models/board.rb

```
class Board < ApplicationRecord
  validates :title, presence: true, length: { maximum: 255 }
  validates :body, presence: true, length: { maximum: 65_535 }

  belongs_to :user
end
```

validatesメソッドは、各カラムにバリデーションを設定するために使用します。presence: trueは値が空でないことを確認し、length: { maximum: *** } は文字数の最大値を制限します。

65_535という書き方は、数値を読みやすくするためにアンダースコアを使用しており、これは65,535と同じ意味です。

belongs_to :userとは、BoardモデルがUserモデルに属していることを示します。この記述により、Boardモデルの各レコードはUserモデルのレコードに関連付けられることになります。

### マイグレーションファイルを編集する

docker compose exec web rails g model Board コマンドで生成されたマイグレーションファイル(`xxxxxxxxxxxxxx_create_boards.rb`)を以下のように編集してください。

- xxxxxxxxxxxxxx_create_boards.rb

```
class CreateBoards < ActiveRecord::Migration[7.0]
  def change
    create_table :boards do |t|
      t.string :title, null: false
      t.text :body, null: false
      t.references :user, foreign_key: true

      t.timestamps
    end
  end
end
```

CreateBoardsマイグレーションファイルには、Boardsテーブルを作成するための記述しています。create_table :boardsブロック内では、テーブルに含まれるカラムを定義しています。

- titleカラム：string型。nullを許容しない設定。
- bodyカラム：text型。nullを許容しない設定。
- user_idカラム：外部キーとしてUserモデルと関連付ける設定。

nullを許容しない設定とは、データベースに保存する際にそのカラムに必ず値を持つことを保証する設定です。

referencesは、外部キーを設定するためのメソッドです。このメソッドを使用することで、BoardsテーブルとUsersテーブルを関連付けることができます。また、foreign_key: true オプションを指定することで、外部キー制約を設定しています。

外部キー制約とは、あるテーブルのカラムの値が、他のテーブルの特定のカラムの値と一致することを強制するデータベースの仕組みです。この制約を設定することで、データベースの整合性を保ち、不整合なデータの挿入を防ぎます。例えば、Boards テーブルの user_id カラムに外部キー制約を設定することで、その user_id が必ず Users テーブルの id カラムに存在することを保証します。

●string型とtext型の違い

- string型
    - 長さ: 255文字までの文字列を扱います。
- text型
    - 長さ: 65,535文字までの文字列を扱います。

### docker compose exec web rails g controller boards コマンドを実行する

### app/controllers/boards_controller.rbにindexアクションを定義する

`app/controllers/boards_controller.rb`を以下のように編集してください。

- app/controllers/boards_controller.rb

```
class BoardsController < ApplicationController
  def index
    @boards = Board.includes(:user)
  end
end
```

includesメソッドは、関連するテーブルをまとめてDBから取得できるメソッドです. Board.includes(:user) は、Boardモデルのレコードと、それに関連するUserモデルのレコードを一度に取得します。これにより、最初のクエリでBoardレコードを取得し、2つ目のクエリで関連するUserレコードを一度に取得するため、クエリの発行回数を2回に抑えてN+1問題に対応しています。

[![Image from Gyazo](https://t.gyazo.com/teams/startup-technology/35280c2a157c3a30bceeacfb019726b9.png)](https://startup-technology.gyazo.com/35280c2a157c3a30bceeacfb019726b9)

N+1問題とは、SQLが必要以上に実行されてしまいパフォーマンスが落ちる問題です。SQLの実行とは、データベースに対してデータの読み書きや検索を行う命令を送信することを意味します。パフォーマンスが落ちるとは、アプリケーションが要求された操作を完了するまでにかかる時間が増加し、全体的な動作速度が遅くなることを意味します。

includesメソッドを使わず、Board.all で取得した場合、掲示板の投稿者名を表示する部分でN+1問題が発生します。

[![Image from Gyazo](https://t.gyazo.com/teams/startup-technology/76b7f9659b97a0ef3d07abd431096fde.png)](https://startup-technology.gyazo.com/76b7f9659b97a0ef3d07abd431096fde)

[![Image from Gyazo](https://t.gyazo.com/teams/startup-technology/758200e17bcabaec84de0090a86753c6.png)](https://startup-technology.gyazo.com/758200e17bcabaec84de0090a86753c6)

データが少ない場合は、クエリがたくさん発行されていてもあまり気にならないかもしれませんが、 データ量が増えてくると、処理が完了するまでにかかる時間も次第に長くなり、アプリケーションのパフォーマンスに悪影響を及ぼします。

●上記コードの解説

- if @boards.present?
    - @boards.present?は、@boardsに値が存在するかどうかを確認します。存在する場合はif以下を実行し、存在しない場合はelse以下を実行します。
- @boards.each do |board| から endまで
    - @boards.eachは、@boardsに含まれる全てのBoardオブジェクトをループ処理します。各Boardオブジェクトはboardとして処理されます。ループ内では、Boardの情報を表示するためのHTMLコードを生成します。
- else以下 <div class='mb-3'>掲示板がありません</div>
    - else以下の部分は、@boardsに値が存在しない場合に実行されます。この場合、「掲示板がありません」というメッセージを表示します。

#### collectionオプションを使わずに記述した場合

```
<% @boards.each do |board| %>
  <%= render 'board', locals: { board: board } %>
<% end %>
```

上記のコードは、@boardsに含まれる各Boardオブジェクトを用いて以下のループ処理を行っています。renderで呼び出しているapp/views/boards/_board.html.erb内で使用されているboard変数（{ board: board }の左側）に、各Boardオブジェクト（{ board: board }の右側）を渡しています。

#### collectionオプションを使って記述した場合

```
<%= render partial: 'board', collection: @boards %>
```

partialには呼び出す部分テンプレートのファイル名を指定し、collectionには繰り返し表示するデータを指定します。この場合、部分テンプレートに渡る変数名はpartialで指定した値（今回でいうとboard）になります。collectionオプションを使う場合は、partialを明示的に記載しないとエラーが出るので注意してください。

#### collectionオプションを使った上で、省略記法を使って記述した場合

collectionオプションを使ったrenderメソッドの記述は、特定の条件を満たした場合にのみ、下記のように省略して記述することができます。

```
<%= render @boards %>
```

#### collectionの省略記法が使える条件

- 部分テンプレートが呼び出し元のテンプレートと同じディレクトリ内にある
- 部分テンプレートのファイル名が指定した変数の単数形である
- 部分テンプレート内で使用する変数名が、オプションで指定した変数の単数形である

### db/seeds.rbを用いてレコードを生成する

Railsコンソールを使ってレコードを生成していくことも可能ですが、共同で開発する際にそうした手間は効率化させておくことが共同開発では大切になります。

以下db/seeds.rbを使用してレコードを生成する例を提示します。

#### db/seeds.rb

db/seeds.rbは、開発環境やテスト環境で使用するデータベースの初期データを設定するためのファイルです。このファイルに記述された内容は、rails db:seedコマンドを実行することでデータベースに適用されます。例えば、ユーザー情報やサンプルデータなど、アプリケーションの動作確認やテストに必要なデータを一括で生成することができます。これにより、開発者は手動でデータを入力する手間を省き、効率的に開発を進めることができます。

`db/seeds.rb`を以下のように記述してください。

- db/seeds.rb

```
10.times do
  User.create!(last_name: Faker::Name.last_name,
              first_name: Faker::Name.first_name,
              email: Faker::Internet.unique.email,
              password: "password",
              password_confirmation: "password")
end

user_ids = User.ids

20.times do |index|
  user = User.find(user_ids.sample)
  user.boards.create!(title: "タイトル#{index}", body: "本文#{index}")
end
```

このコードは、gem 'faker'を使用してランダムなユーザーと掲示板レコードを生成します。 まず、10.timesブロックで10人のユーザーを生成します。各ユーザーにはランダムな姓、名、ユニークなメールアドレス、そして固定のパスワードが設定されます。次に、全てのユーザーIDを取得し、user_ids配列に格納します。20.timesブロックでは、ランダムに選ばれたユーザーに関連付けられた掲示板レコードを20個生成します。各掲示板レコードには、タイトルと本文が設定されます。

gem 'faker'とは、ランダムなデータを生成するためのRubyライブラリです。このライブラリは、開発環境やテスト環境で使用するダミーデータを簡単に生成することができます。

上記コードを記載したらターミナルにて以下のコマンドを実行してください。

```
$ docker compose exec web rails db:seed
```
