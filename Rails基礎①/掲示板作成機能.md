## `git commit`とは

`git commit`とは、Gitで管理しているファイルの変更内容を**1つの履歴として保存する操作**を指す

## 理想的なコミット

理想としては、  **1コミット = 1つの明確な変更**
> **意味のある1つの変更が完了したタイミング** をコミットの目安にすると分かりやすい

## なぜコミットを適切な粒度に分けるのか

コミットを適切な単位で分けておくことで、以下のメリットがある
- 何を変更したのか確認しやすくなる
- バグが発生した原因を探しやすくなる
- コードレビューをしやすくなる
- 過去の状態を確認しやすくなる
- 他の開発者が変更内容を理解しやすくなる
### Lintとは

**コードの書き方やルールに問題がないかを確認する仕組み**を指す

例えば、 以下の問題を検出できる
```text
インデントがおかしい
不要な空白がある
Rubyの一般的な書き方に反している
```


## `git add`と`git commit`の違い

`git add ファイル名`は、**次のコミットに含める変更を選択する操作**を指す。

## ステージングエリア

`git add`した変更は、**ステージングエリア**と呼ばれる場所に追加される
> 次のコミットに含める変更を一時的に置いておく場所 を指す。




```ruby
def create
  @board = current_user.boards.build(board_params)

  if @board.save
    redirect_to boards_path,success: t('defaults.flash_message.created',
    item: Board.model_name.human
	 )
  else
    flash.now[:danger] = t(
      'defaults.flash_message.not_created',
      item: Board.model_name.human
    )

    render :new, status: :unprocessable_entity
  end
end
```

### current_user.boards

**現在ログインしているユーザーに紐づくBoard**を扱うことを意味する。
