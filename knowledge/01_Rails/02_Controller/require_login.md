# require_login

## 📌 一言でいうと

**ログインしているユーザーだけが操作できるように、ログイン状態を確認するメソッド。**

## 📖 仕組み・役割

`before_action` と組み合わせて、**アクションを実行する前にログイン状態を確認**します。

- **ログイン済み** → アクションの処理に進む
- **未ログイン** → ログイン画面へ移動させるなど、アプリで定めた処理を行う


## 💻 コード例

```ruby
class BoardsController < ApplicationController
  before_action :require_login, only: [:new, :create]

  def new
    @board = Board.new
  end

  def create
    # 掲示板を保存する処理
  end
end
```

|コード|意味|
|---|---|
|`before_action`|アクションの実行前に指定したメソッドを呼ぶ|
|`:require_login`|呼び出すメソッドの名前|
|`only: [:new, :create]`|`new` と `create` の前だけ実行する|

つまり、**「掲示板の新規作成画面を開くときと、投稿するときにログインを確認する」**という指定です。


## 🎯 使用場面

- ログインした人だけが掲示板に投稿できるようにする
- プロフィール編集にログインを必須にする
- 会員専用ページへのアクセスを制限する


## ⚠️ 注意点・よくある間違い

**① Rails標準のメソッドではない**

認証ライブラリが提供しているか、自分で定義する必要があります。名前を書くだけで使えるわけではありません。

**② `before_action` と役割が違う**

- `before_action`：**いつ呼ぶか**を指定する
- `require_login`：**ログイン状態を確認する処理**を担当する

**③ ログイン確認と、編集権限の確認は別**

ログイン済みでも、他人の投稿を編集してよいとは限りません。**「投稿した本人かどうか」などは別途確認が必要**です。

**④ `params.require` とは別物**

`params.require(:user)` は受信データを取り出すメソッドで、ログイン確認には使いません。

## 🔄 復習メモ

### Q1. `require_login` は何をするメソッド？

ログインが必要な操作の前に、ログイン状態を確認するメソッド。

### Q2. `require_login` はどこで使う？

基本的にControllerで、`before_action` と組み合わせて使う。

### Q3. `only: [:new, :create]` はどういう意味？

`new` と `create` アクションの前だけ実行する指定。

### Q4. `require_login` があれば、他人の投稿の編集も防げる？

それだけでは防げない。投稿者本人かどうかなど、操作する権限の確認も必要。
